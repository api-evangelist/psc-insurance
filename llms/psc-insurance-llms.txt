# PSC Insurance

> PSC Insurance Brokers is an Australian commercial and SME insurance broking
> intermediary operating across every Australian state and territory, with a New
> Zealand arm trading as PSC Broking. It advises clients and places risk with
> insurers rather than carrying underwriting risk itself. Formerly the ASX-listed
> PSC Insurance Group, the business now sits inside The Ardonagh Group's Australian
> distribution platform (Envest). **PSC publishes no public API, no developer portal
> and no machine-readable API contract.** This file exists so an agent stops looking
> for one, and knows precisely which machine-facing surfaces do and do not exist.

## What does not exist

Every one of these was probed and confirmed absent. Do not attempt to discover them
again without new evidence.

- No developer portal. developer/developers/docs/api subdomains do not resolve;
  /developers, /developer, /api, /partners and /integrations all return HTTP 404.
- No OpenAPI or Swagger definition on any PSC host.
- No GraphQL API. /graphql returns 404 on the website, and the Sanity project has no
  GraphQL schema deployed ("GraphQL schema not found for dataset/tag").
- No webhooks, no event catalogue, no PSC-published AsyncAPI.
- No SDK or client library on npm, PyPI, or any other registry. No GitHub organisation.
- No public Postman collection or workspace.
- No MCP server and no agent skills.
- No ACORD, ACORD XML, AL3, NGDS or IVANS/agency-download reference anywhere.
- No status page, no changelog, no deprecation policy, no published SLA.
- None of the four insurance verbs is exposed: quote, bind, issue and FNOL are all
  human-mediated. Claims are lodged through a web page and a broker, not an API.

## Machine-facing surfaces that do exist

Neither is a PSC developer product. Both are third-party platforms under PSC
tenancy, and PSC documents neither.

- Identity — Auth0 custom domain fronting a gated client/broker login:
  https://login.pscinsurance.com.au/.well-known/openid-configuration (HTTP 200)
- OAuth 2.0 authorization server metadata (RFC 8414):
  https://login.pscinsurance.com.au/.well-known/oauth-authorization-server (HTTP 200)
- JWKS: https://login.pscinsurance.com.au/.well-known/jwks.json (HTTP 200)
- Content Lake — the Sanity dataset backing the marketing site, readable anonymously:
  https://tw8a70my.api.sanity.io/v2021-10-21/data/query/production?query=* (HTTP 200)
- Real-time mutation stream (Server-Sent Events) on the same dataset:
  https://tw8a70my.api.sanity.io/v2021-10-21/data/listen/production (HTTP 200)
- security.txt (RFC 9116):
  https://www.pscinsurance.com.au/.well-known/security.txt (HTTP 200)

The identity tenant advertises only standard OpenID Connect and Auth0 profile-claim
scopes. There is no PSC audience, resource server or product scope. Do not read the
advertised grant types as evidence of an API programme.

The Content Lake holds marketing content only — pages, blog articles, office
locations, authors, categories, site settings. It holds no policy, quote, claim,
client or premium data.

## Why there is no API

Australia has the legal machinery for open insurance and no live obligation. The
Consumer Data Right that opened banking and energy was designated to extend to
general insurance and then deferred and de-prioritised, so no forcing function ever
reached brokers. For a broker-intermediary of this shape, integration is
partner-gated and mediated through broker platforms and insurer relationships, with
nothing exposed publicly. If a surface ever appears, it is more likely to appear
under Envest/Ardonagh than under pscinsurance.com.au.
